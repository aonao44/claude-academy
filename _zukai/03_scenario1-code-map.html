オレンジ = Anthropic の仕様で固定（変えると動かない） 青緑 = 自分で決めた名前（自由に変えられる） 灰色の斜体 = 実行時に決まる値 点線付きオレンジ = JSON Schema の語（これも仕様で固定）

API78–81行目だけが Anthropic とのやりとりです。自分の関数124行目で tools.py の関数を呼んでいます。A のガード107–118行目は、自分の関数を呼ぶ前に止める関門です。

  • ③返ってきた content はブロックのリストです。type が "text" なら Claude の発言、"tool_use" なら「このツールを呼んでほしい」という依頼です。

03tools.py：Claude に渡す説明書と、実際の関数

同じ get_customer という名前が2か所に出てきますが、役割が違います。DEFS は Claude に渡す説明書、IMPL は自分のコードが呼ぶ関数です。

境界を越えるDEFS（L92〜）＝ 説明書

92①DEFS = [
{
"name": "get_customer",
"description": "顧客を本人確認する…",
"input_schema": {
"type": "object",
"properties": {
"email": {"type": "string"},
"name": {"type": "string"}}},
}, # lookup_order / process_refund / …
]

外側のキー name / description / input_schema は Anthropic の仕様で決まっています。その中身、つまりツール名・説明文・引数名 email は自分で決めたものです。type properties などは JSON Schema の書き方です。

なお、"name"（引数名）は外側の "name"（ツール名のキー）とは無関係で、たまたま同じ綴りなだけです。

境界を越えないIMPL（L83）＝ 実体

30def get_customer(email=None, name=None):
# infra/db.py 経由で shop.db を検索する
return {"customer_id": …, "verified": True}
⋮
83④IMPL = {
"get_customer": get_customer,
"lookup_order": lookup_order,
"process_refund": process_refund,
"escalate_to_human": escalate_to_human,
}

ここは全部が青緑です。Anthropic の仕様はまったく出てきません。Claude がこのファイルの中身を見ることはなく、関数を直接呼ぶこともありません。

守る必要があるのは「DEFS の name と IMPL のキーを揃える」「input_schema の引数名と関数の引数名を揃える」の2点だけです。これは **b.input で引数を展開して渡すために、自分で決めた約束事です。

04境界を越えるデータの中身

①②⑥で実際にネットワークを流れる JSON です。Python のコードは SDK によってこの形に変換されます。

① 渡す（リクエスト）

{
"model": "claude-haiku-4-5",
"max_tokens": 700,
"system": "あなたはECサイトの…",
"tools": [ /* DEFS の4本 */ ],
"messages": [
{"role": "user",
"content": "田中です。先週注文した…"}

}

モデル ID の "claude-haiku-4-5" は Anthropic が決めた値です。どれを使うかは自分で選びますが、綴りは変えられません。

② 返る（レスポンス ＝ res）

{
"type": "message", "role": "assistant",
"stop_reason": "tool_use",
"content": [
{"type": "text", "text": "お調べします。"},
{"type": "tool_use",
"id": "toolu_01A…",
"name": "lookup_order",

青緑の名前は、自分が DEFS に書いた名前がそのまま返ってきたものです。灰色の値（"田中"、ID など）は Claude がその場で決めています。事故の原因は、この "田中" だけで注文を引こうとしたことです。

⑥ 再び渡す（messages に2件追加）

"messages": [
{ /* ① の user */ },
{"role": "assistant", "content": [ /* ②の content */ ]},

"tool_use_id": "toolu_01A…",

API はステートレスで、前回のやりとりを覚えていません。そのため毎回、履歴全体を渡し直します。tool_use_id には②の id をそのまま入れます。

シナリオ1 ・ Claude Agent SDK の全体像

Agent SDK のサポートエージェント

「Claude Agent SDK でカスタマーサポートのエージェントを作る」とは、何がどこにあって、何が誰の仕事なのか。返金1件の流れで追います。図の中のサーバー名やデータはすべて説明用の例です。

1どこに何があるか

登場するのは3つの場所です。あなたのサーバーの中に、あなたのアプリと Agent SDK が同居しています。Claude は Anthropic 側にいて、データベースには一切触れません。

あなたが書く・作るもの Agent SDK がやってくれること Anthropic 側（Claude）
練習用コード labs/scenario1-no-mcp/agent.py との違い：あちらは紫の部分（ループ・ツールの実行）を全部自分で書いていました。Agent SDK を使うと、紫の部分は SDK が受け持ち、あなたは緑の部分（設定とツールの中身）に集中できます。Claude 側の仕組みはどちらも同じです。

2返金1件の流れ

顧客「先週買った靴を返品して返金してほしい。メールは hanako@example.com です」（例）

アプリ顧客の文と設定を query() に渡す。

SDKsystem・tools（4つの MCP ツール）・messages を Claude に送る。

Claude「まず本人確認」と判断し、tool_use: get_customer {email: "hanako@…"} を返す。

SDKMCP サーバーの get_customer を実行し、結果（顧客ID C-2044）を tool_result にして Claude に送り返す。

Claudelookup_order → process_refund と、同じ往復を繰り返す。

SDKprocess_refund を実行。ここで返金が失敗したとする（次の節）。

Claude失敗の中身を読んで、次の手を決める。最後は文章だけを返す（stop_reason: end_turn）。

SDKループを終え、最終回答をアプリに返す。アプリそれを顧客に表示する。

3失敗をどう返すか（問題 1.6）

6番目で process_refund が失敗したとき、MCP サーバー（あなたのコード）が返す tool_result の中身で、Claude の次の一手が変わります。Claude は、渡された文字しか見られません（原則④）。

今：理由が分からない

tool_result:
"Operation failed."

決済システムの一時停止でも、返品期限切れでも、同じ文字列。Claude には区別がつかないので、方針で禁止された返金をやり直したり、少し待てば通る障害で諦めたりする。

D：理由と次の手が分かる

tool_result:
{ "errorCategory": "business",
  "isRetryable": false,
  "description": "返品期限（30日）を
    過ぎているため返金できません" }

Claude は「やり直しても無駄。顧客に期限切れを説明しよう」と判断できる。

errorCategory例isRetryableClaude の正しい動き
transient（一時的）決済システムが30秒止まっていたtrue少し待ってやり直す
validation（入力の誤り）注文番号の形式が違うfalse（直してからなら可）入力を直して呼び直す
business（業務ルール違反）返品期限切れ、500ドル超false顧客に理由を説明する／人間に回す
permission（権限なし）このエージェントには返金の権限がないfalse人間に回す

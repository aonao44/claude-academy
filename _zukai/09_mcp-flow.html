MCP ・ Gmail を例に

MCP はこう走る

「未読の請求メールを要約して」と頼んでから答えが返るまでに、どのプログラムがどこで動き、何がどの順番で流れるか。サーバーやメールの中身は説明用の例です。

1一番大事なこと：会話は2本ある

Claude と MCP サーバーは、直接つながっていません。真ん中のクライアントが、性質の違う2本の会話を同時に受け持ち、間で中継しています。

MCP（規格）が決めているのは会話②の話し方だけです。会話①は、これまで練習用コード labs/scenario1-no-mcp/agent.py で見てきた Messages API（system・tools・messages を送り、tool_use が返る）そのものです。

2最初から最後までの流れ

縦に時間が流れます。オレンジの線が会話①、紫の線が会話②、緑の線は MCP サーバーと Gmail の間（MCP とは関係のない、Google の API）です。

番号何が起きているかどの会話か
①②クライアントが起動すると、つないである MCP サーバーに「何ができる？」と聞き、ツールの一覧を受け取っておく。まだ Claude は関わっていない会話②（MCP）
③④あなたの依頼が来たら、クライアントは②で受け取った一覧を tools に詰めて Claude に送る。Claude から見れば、練習用コードの tools.py で自分で書いたツールと区別がつかない会話①
⑤Claude は tool_use（依頼の箱）を返すだけ。Gmail には触れない会話①
⑥クライアントが「実行してよいか」を判断する場所。送信のような危険な操作はここで止めたり、人間に確認したりできる―
⑦〜⑨クライアントが MCP の決まった形で呼び出し、サーバーが Gmail API で検索して結果を返す会話②＋Google の API
⑩結果を tool_result の箱にして messages に足し、Claude に送り直す（原則④：渡さないと Claude は知らない）会話①
⑪⑫tool_use が来なくなったら（end_turn）、最終回答を表示して終わり会話①

3クライアントと MCP サーバーはどこで動くか

構図はいつも同じで、どのプログラムがクライアント役をするかと、サーバーがどこにあるかだけが変わります。

使っているものクライアント役MCP サーバーの置き場の例
Claude アプリ（claude.ai・スマホ）claude.ai のサービス（Anthropic 側）インターネット上（コネクタ）
Claude Codeあなたのパソコンで動く Claude Codeインターネット上、またはパソコン上で一緒に起動するプログラム
自作のエージェント（Agent SDK）あなたのプログラム（SDK が中継を受け持つ）どちらも可

4練習用コードとの関係

labs/scenario1-no-mcp/ では、ツールの中身（tools.py）を自分のプログラムの中に直接書いていました。つまり、会話②がなく、⑦〜⑨の代わりに自分の関数を直接呼んでいます。MCP にすると、その関数が別のプログラム（MCP サーバー）に引っ越し、間を MCP の決まった話し方でつなぐことになります。Claude 側（会話①）は何も変わりません。

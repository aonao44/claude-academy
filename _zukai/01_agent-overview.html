エージェントの全体像 ― Claude API で何が起きているか

CCAR-F 学習用 / 図は3枚。① 誰が何をしているか ② 履歴が伸びる様子 ③ ループの終わり方

1所有権の境界

主張：Claude は「次に何をすべきか」を答えるだけ。DB も決済APIも触らない。触るのは全部自分のコード。

2ステートレス ― 履歴が毎周伸びる

主張：サーバーは何も覚えていない。会話が続いているように見えるのは、送る側が毎回すべてを積み直しているから。

3ループの終わり方

主張：stop_reason の分岐がループの心臓。公式 In-Scope の筆頭項目がこれ。

5エンジンはこれで全部。あとは周りに何を付けるか

主張：図の3枚に描いたものが、エージェントの動力部のすべて。隠れた仕掛けは無い。残りは全部「このエンジンの周りに何を足すか」。

labs/scenario1-no-mcp/ は上の3枚をそのままコードにしたもの。stop_reason を見て回すループ、ツールの実体、伸びる履歴、そして決定論的なガード — それだけで公式サンプル問題1の事故が再現でき、直せる。

図①でいうと、増えるのは「自分が用意するもの」の箱の中身だけ。Anthropic 側は何も変わらない。だから設計の余地が全部こちら側にあり、それが「アーキテクト」という試験名の意味になる。

そしてこの上にもう一層ある — ループエンジニアリング（プロンプトを打つ人の座から自分を外し、それを回す仕組みを設計する層）。ただし CCAR-F の出題範囲はハーネス層までで、そこは問われない。

## なぜ分けるのか

公式シナリオ1の原文は **「custom MCP tools を通じてバックエンドに接続する」** と書いている。
`scenario1-no-mcp/` はそこを意図的に外し、**同一プロセスの Python 関数**にしてある。

外した理由は「MCP が難しいから」ではなく、**ループを見えるようにするため**。
MCP を先に入れるとプロセス境界と設定ファイルが増え、
`stop_reason` の分岐や `messages` の伸び方という本題が埋もれる。

**土台（no-mcp）→ 置き換え（mcp）の順にすると、差分だけを見られる。**

---

## 何が変わるか

| 観点 | no-mcp（いま） | mcp（これから） |
|---|---|---|
| ツール定義の入手 | `tools.py` の `DEFS` をハードコード | **サーバーに `tools/list` で問い合わせる** |
| ツールの実行 | `IMPL[name](**input)` ＝ 関数呼び出し | **`tools/call` を JSON-RPC で送る** |
| エラーの返し方 | `{"error": ...}` を自分で詰める | **`isError` フラグ**（MCP の仕様） |
| 設定 | なし | **`.mcp.json`**（プロジェクト/ユーザースコープ・環境変数展開） |
| 起動 | `python agent.py` | サーバーを子プロセスとして起動（stdio） |
| 再利用 | この `agent.py` 専用 | **Claude Code からも同じサーバーを使える** |
| 読み取り専用データ | 概念なし | **Resources**（カタログ）と **Tools**（行為）の使い分け |
| **ガードの置き場所** | クライアント（`agent.py`）の `if` | **クライアント側 or サーバー側の選択が発生** |

## 何が変わらないか

**この lab で学んだことは全部そのまま効く。**

- `stop_reason` を見て回すループ
- `tool_use` / `tool_result` の往復と `tool_use_id` での対応づけ
- `messages` が毎周伸びること
- `description` がツール選択を決めること
- Claude が受け取るのは説明書だけで、関数の実体には触れないこと

**MCP はツールの置き場所を変える規格であって、エージェントの動き方を変えるものではない。**

## ★ 新しく生まれる論点：ガードをどちらに置くか

`scenario1-no-mcp` では、サンプル問題1の対策 A（本人確認前は `lookup_order` を実行しない）を
**クライアント側（`agent.py` の `if`）** に書いた。MCP 版では選択肢が2つになる。

| 置き場所 | 効く範囲 | 弱点 |
|---|---|---|
| **クライアント側** | この `agent.py` だけ | 同じ MCP サーバーを他から使われると素通り |
| **サーバー側** | **そのサーバーを使う全員** | サーバーが呼び出し元の状態（本人確認済みか）を知る必要がある |

**シナリオ1が「MCP tools でバックエンドに接続する」と書いている以上、
実運用ではサーバー側に置くのが筋**——だが、そのためには
「誰の、どのセッションの本人確認が済んでいるか」をサーバーが持つ必要が出てくる。
ここは出題されうる設計判断。

## 実装するときの手順（予定）

1. `server.py` — `scenario1-no-mcp/tools.py` の `IMPL` を MCP サーバーとして公開（stdio）
2. `.mcp.json` — サーバーの起動方法を定義。**環境変数展開を1つ使う**（In-Scope 項目）
3. `agent.py` — `DEFS` のハードコードを `tools/list` に、`IMPL[...]()` を `tools/call` に置換
4. エラーを `isError` で返すよう変更
5. **ガードをサーバー側へ移し**、クライアント側から消しても事故が防げるか確認
6. Claude Code の `.mcp.json` に登録し、**同じサーバーが Claude Code からも使えること**を確認

## 範囲の注意（§17）

- **In-Scope**：MCP の**設定**（スコープ・環境変数展開・複数サーバー同時利用）、
  **設計**（Resources と Tools の使い分け・description の質・構造化エラー）
- **Out-of-Scope**：MCP サーバーの**デプロイ・ホスティング**（インフラ・ネットワーク・コンテナ）
